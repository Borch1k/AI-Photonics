# PINN: четыре изображения → фазовая маска и реконструкции

Материалы защиты: [презентация PPTX](main.pptx)

Один контейнер, две обученные FFN PINN: `lens` (с линзами) и `no_lens` (без линз). Выбранная сеть за один проход выдаёт начальную фазовую маску. Затем выполняется дооптимизация Adam: **число шагов задаётся `--refine-steps`, по умолчанию 100**, learning rate 0,05; сохраняется лучшая найденная маска. Из окончательного 8-битного PNG маски рассчитываются четыре реконструкции. Повторного обучения сети при запуске нет.

## Состав репозитория

- `photonics.py` — исходный код FFN PINN, загрузка моделей, обе оптические схемы и дооптимизация.
- `optics.py` — параметры оптики и кодирование фазы.
- `pipeline.py` — общий pipeline и CLI.
- `models/pinn_lens.pt`, `models/pinn_no_lens.pt` — обе обученные модели, включаемые в Docker-образ.
- `models/manifest.json` — происхождение весов, параметры и SHA-256.
- `Dockerfile`, `requirements.txt` — сборка и зависимости.
- `test_pipeline.py` — проверки порядка вычислений и формата результата.

## Сборка

Из корня репозитория, с запущенным Docker Engine / Docker Desktop в режиме Linux containers:

```bash
docker build -t photonics-pinn .
```

Зависимости загружаются при сборке. Веса уже находятся в репозитории и копируются в образ. При обработке изображений интернет и сервер обучения не требуются. Образ работает на CPU; GPU для запуска не нужен.

## Запуск

В `input/` уже лежит пример из четырёх изображений `1.png`…`4.png`. Замените их своими и создайте `output/`. Имена входных файлов произвольные; порядок четырёх аргументов соответствует порядку выходных реконструкций.

Linux / macOS:

```bash
mkdir -p output
docker run --rm --network none \
  -v "$PWD/input:/input:ro" \
  -v "$PWD/output:/output" \
  photonics-pinn --mode lens \
  --images /input/1.png /input/2.png /input/3.png /input/4.png
```

PowerShell:

```powershell
New-Item -ItemType Directory -Force output | Out-Null
docker run --rm --network none `
  --mount "type=bind,source=$((Get-Location).Path)/input,target=/input,readonly" `
  --mount "type=bind,source=$((Get-Location).Path)/output,target=/output" `
  photonics-pinn --mode lens `
  --images /input/1.png /input/2.png /input/3.png /input/4.png
```

**Для варианта без линз замените `--mode lens` на `--mode no_lens`.** Всё остальное одинаково. Другой каталог внутри контейнера можно задать через `--out`. Входные изображения переводятся в grayscale и билинейно масштабируются до 128×128. Передавайте светлые символы на тёмном фоне, как при обучении; автоматической инверсии нет.

Количество шагов задаётся после имени образа вместе с остальными параметрами:

```text
photonics-pinn --mode lens --refine-steps 250 --images /input/1.png /input/2.png /input/3.png /input/4.png
```

`--refine-steps 0` сохраняет маску непосредственно от PINN без дооптимизации, затем рассчитывает из неё реконструкции. При отсутствии параметра выполняются 100 шагов. Допускаются только целые неотрицательные значения. Для Python CLI используется тот же параметр.

## Результат

В смонтированном `output/` появятся ровно пять файлов:

```text
output/
  phase_mask.png
  reconstruction_1.png
  reconstruction_2.png
  reconstruction_3.png
  reconstruction_4.png
```

Каждый PNG — **128×128, grayscale (режим L), 8 бит**, без осей, подписей, рамок и цветовой палитры. Для фазовой маски `phase = code × (2π / 255) − π`: 0 соответствует −π, 255 соответствует +π. Для реконструкций 0 — чёрный, 255 — белый. Это grayscale, не бинарный формат из двух уровней.

Реконструкции вычисляются из перечитанной `phase_mask.png`, поэтому учитывают её реальное 8-битное квантование. Для перевода физической интенсивности в PNG используется тот же коэффициент, что при обучении: средняя интенсивность соответствующего входа, затем обрезка до [0,1]. Независимого растяжения контраста каждой реконструкции нет.

Оптические параметры берутся из выбранного checkpoint: длина волны 532 нм, шаг маски 10 мкм, расстояния 24,1 / 25,3 / 26,5 / 27,7 мм. Для линзовой модели мощности линз фиксированы: 80 / 55 / 30 / 10 дптр. Примеры исходных PINN приведены в `REPORT_FFN.md`.

## Запуск без контейнера и тесты

```bash
pip install -r requirements.txt
python pipeline.py --mode lens --images input/1.png input/2.png input/3.png input/4.png --out output
python -m unittest test_pipeline
```

В существующем CUDA-окружении Python можно добавить `--device cuda`. Стандартный Docker-образ содержит CPU-версию PyTorch.

## Выполненные проверки

Образ `photonics-pinn` успешно собран. Оба режима запущены в реальном контейнере с `--network none` на четырёх примерах из `input/`. В каждом случае получены ровно пять PNG 128×128, grayscale, 8 бит. Результаты пробного запуска находятся в `checks/docker_lens/` и `checks/docker_no_lens/`.

`test_pipeline.py` проверяет обе схемы: один вызов модели до создания симулятора, 100 обновлений по умолчанию, заданное число обновлений, отсутствие оптимизации при нуле, отклонение некорректных значений, формат PNG и попиксельное совпадение реконструкций с расчётом из экспортированной фазовой маски. Также прошли десять существующих тестов физики и нейросетей из `test_photonics.py`.

## Git и обученные веса

Файлы весов находятся в `models/`; каждый занимает около 203 МБ. В `.gitattributes` настроен Git LFS для `models/*.pt`. Перед первым коммитом выполните:

```bash
git init
git lfs install
git add .
git commit -m "Add PINN Docker pipeline and trained models"
```

После клонирования репозитория выполните `git lfs pull`, чтобы получить полные файлы весов перед сборкой Docker-образа.
